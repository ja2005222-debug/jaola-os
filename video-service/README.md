# 🎬 استوديو الفيديو — JAOLA Video Service

خدمة **مستقلة كلياً** عن منصة JAOLA الرئيسية: صفر استيراد من `backend/`،
تُنشر وتتوسع وتتعطل (لا قدّر الله) بمعزل تام عن المنصة. الرابط الوحيد
بينهما هو **الدخول الموحّد**: الخدمة تتحقق محلياً من نفس توكن JWT الصادر
من المنصة (نفس `JWT_SECRET`) — المستخدم يسجّل دخوله مرة واحدة.

## المعمارية

```
المنصة الرئيسية (backend/)            خدمة الفيديو (video-service/)
  إصدار التوكن (login) ────────────────▶ تحقق محلي بنفس JWT_SECRET
                                          │
                                          ├─ نظام أرصدة مسبقة الدفع
                                          │   (خصم قبل التنفيذ، استرداد عند الفشل،
                                          │    سجل تدقيق append-only)
                                          ├─ طابور مهام دائم (jobs.json)
                                          │   queued → rendering → done|failed
                                          ├─ طبقة مزودين قابلة للتبديل
                                          │   mock (افتراضي) / shotstack / (fal.ai لاحقاً)
                                          └─ واجهة استوديو ذاتية (public/)
```

## التشغيل محلياً

```bash
cd video-service
npm install
JWT_SECRET=<نفس سر المنصة> npm start   # المنفذ الافتراضي 4100
```

بلا أي مفاتيح إضافية تعمل الخدمة بوضع **المحاكاة**: دورة كاملة (طابور →
تصدير → اكتمال) بلا تكلفة وبلا ملف فيديو فعلي — مثالية للتطوير والعرض.

## متغيرات البيئة

| المتغير | إلزامي؟ | الوصف |
|---|---|---|
| `JWT_SECRET` | ✅ | **نفس** سر المنصة الرئيسية — هذا هو الدخول الموحّد |
| `ADMIN_USERS` | — | نفس قائمة مشرفي المنصة (أسماء مفصولة بفواصل) |
| `PORT` | — | المنفذ (افتراضي 4100) |
| `DATABASE_URL` | للإنتاج | رابط PostgreSQL (Neon/Supabase مجاناً). **بدونه التخزين ملفات على قرص قد يكون مؤقتاً** |
| `VIDEO_DATA_DIR` | — | مجلد البيانات حين لا يُضبط `DATABASE_URL` (افتراضي `.videostudio/`) |
| `VIDEO_PROVIDER` | — | مزوّد **التركيب**: `mock` (افتراضي) أو `shotstack` |
| `VIDEO_AI_PROVIDER` | — | مزوّد **التوليد بالذكاء الاصطناعي**: فارغ/`none` (معطَّل) أو `fal` أو `mock` |
| `FAL_KEY` | مع fal | مفتاح fal.ai |
| `FAL_MODEL` | — | نموذج افتراضي يدوي (مثال: `fal-ai/veo3/fast`) — اختياري منذ كتالوج النماذج؛ إن ضُبط صار الافتراضي ويُضاف كخيار إن لم يكن في الكتالوج |
| `FAL_IMAGE_MODEL` | — | نموذج توليد الصور المرجعية لبنك الشخصيات (افتراضي `fal-ai/flux/schnell` — سريع ورخيص) |
| `FAL_TTS_MODEL` | — | نموذج تعليق صوتي (TTS) — لا افتراضي عمداً؛ بدونه خيار التعليق الصوتي مخفي كلياً (راجع ⚠️ أدناه) |
| `FAL_TTS_VOICE` | — | معرّف الصوت/المتحدث اختيارياً حسب النموذج المختار — يُرسل فقط عند ضبطه |
| `MUSIC_LIBRARY_JSON` | — | مكتبة موسيقى التجميع المرخصة `[{id, nameAr, url}]` — بدونها خيار الموسيقى يُخفى |
| `SFX_LIBRARY_JSON` | — | مكتبة مؤثرات صوتية للانتقال `[{id, nameAr, url}]` — بدونها خيار المؤثر يُخفى |
| `WATERMARK_ENFORCEMENT` | — | `true` لفرض علامة مائية على تجميعات الخطة المجانية — **معطَّل افتراضياً** (راجع ⚠️ أدناه قبل تفعيله) |
| `WATERMARK_TEXT` | — | نص العلامة المائية (افتراضي `JAOLA OS`) |
| `FAL_MODELS_JSON` | — | **توسيع كتالوج النماذج بلا نشر كود**: مصفوفة `[{id, nameAr, falPath, costCredits, aspectRatios, descriptionAr}]` — نفس `id` لنموذج مدمج يستبدله (لتعديل تكلفته مثلاً)، وإعدادٌ فاسد يوقف الإقلاع صاخباً |
| `SHOTSTACK_API_KEY` | عند اختيار shotstack | من لوحة Shotstack |
| `SHOTSTACK_ENV` | — | `stage` (افتراضي — مجاني بعلامة مائية) أو `v1` (إنتاج مدفوع) |
| `JWT_SECRET_PREVIOUS` | — | السر السابق — يُقبل للتحقق **أثناء تدوير المفتاح فقط** |
| `DAILY_RENDER_CAP` | — | سقف التوليد اليومي لكل الخدمة (افتراضي 200، و**0 يوقف التوليد تماماً**) |
| `DAILY_RENDER_CAP_PER_USER` | — | سقف المستخدم الواحد يومياً (افتراضي 20) |
| `COST_ALERT_AT_PCT` | — | ٪ من السقف يُرسَل عندها التنبيه (افتراضي 80) |
| `COST_ALERT_WEBHOOK_URL` | — | رابط يستقبل تنبيه التكلفة (Slack/Discord/أي endpoint) |
| `STARTER_CREDITS` | — | الرصيد الترحيبي المجاني (افتراضي 3، **و0 يعطّله كلياً**) |
| `CONTENT_BLOCKLIST` | — | مصطلحات محظورة مفصولة بفواصل |
| `VIDEO_STORAGE` | — | `r2` لتفعيل ملكية الملفات (بدونه تبقى لدى المزوّد) |
| `R2_ACCOUNT_ID` | مع r2 | معرّف حساب Cloudflare |
| `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` | مع r2 | مفاتيح R2 API |
| `R2_BUCKET` | مع r2 | اسم الدلو (يبقى **خاصاً**) |
| `S3_ENDPOINT` | — | لمزوّد S3 آخر بدل R2 |
| `SIGNED_URL_TTL_SEC` | — | عمر رابط التنزيل الموقّع (افتراضي 600 ثانية) |
| `VIDEO_RETENTION_DAYS` | — | حذف تلقائي بعد N يوماً (افتراضي 30، و**0 = احتفاظ دائم**) |
| `VIDEO_SCRIPT_API_KEY` | — | مفتاح مزوّد **تخطيط السيناريو** ("خطّط لي فيلماً" — برومت واحد → مسودة مشاهد متعددة). بدونه الميزة مخفية بالكامل |
| `VIDEO_SCRIPT_API_URL` | — | نقطة نهاية متوافقة مع OpenAI chat/completions (افتراضي Groq: `https://api.groq.com/openai/v1/chat/completions`) |
| `VIDEO_SCRIPT_MODEL` | — | نموذج التخطيط (افتراضي `llama-3.3-70b-versatile`) |

## 🛡️ درع التكلفة (اقرأه قبل تفعيل مزوّد مدفوع)

الأرصدة مسبقة الدفع درعٌ بنيوي، لكن فيه ثقب: **الرصيد الترحيبي المجاني**.
مع مزوّد حقيقي، كل حساب جديد = توليدات مدفوعة عليك، فتعرّضك =
(عدد المسجَّلين) × `STARTER_CREDITS`. لذا:

- **قبل تفعيل Shotstack المدفوع**: اضبط `STARTER_CREDITS=0` أو قيمة صغيرة
  جداً، واضبط `DAILY_RENDER_CAP` بما يعادل أقصى فاتورة يومية تقبلها.
- **إيقاف طوارئ فوري**: `DAILY_RENDER_CAP=0` يوقف كل توليد جديد حالاً.
- **المتابعة**: `/api/video/admin/status` يعرض `usage.usedToday` و
  `remainingToday`، وتصلك رسالة على `COST_ALERT_WEBHOOK_URL` مرة واحدة
  يومياً عند بلوغ النسبة المحددة.

## 🤖 توليد الفيديو بالذكاء الاصطناعي (المرحلة ٢)

الخدمة تنتج الآن **نوعين** مختلفين جذرياً، لكل نوع مزوّده:

| النوع | المدخل | المزوّد | الأمثلة |
|---|---|---|---|
| `timeline` | قوالب بحقول | `VIDEO_PROVIDER` | إعلان ترويجي، عرض منتج، قصة |
| `ai_prompt` | وصف نصي حر | `VIDEO_AI_PROVIDER` | مقطع بالذكاء الاصطناعي |

المخطط المُجمَّع يحمل `kind`، و**الموجّه** في `src/providers/index.js` يرسل
كل نوع لمزوّده ويعيد الاستطلاع للمزوّد نفسه (المعرّف يحمل بادئة النوع).

### التفعيل
```
VIDEO_AI_PROVIDER=fal
FAL_KEY=<مفتاحك من fal.ai>
```

**بلا هذين المتغيرين القالب يُخفى من الكتالوج ويُرفض طلبه المباشر** — لا
نعرض ميزة تفشل عند أول ضغطة.

### 🎞️ كتالوج النماذج (متعدد النماذج — الاستوديو السينمائي)

المستخدم يختار **النموذج لكل لقطة** من كتالوج (`src/models.js`)، ولكل
نموذج تكلفته بالأرصدة ونسب أبعاده المدعومة — يتحقق منها الخادم لا
الواجهة فقط. الكتالوج المدمج يضم نماذج تحققنا من مساراتها في الإنتاج
(Veo 3 السريع والكامل)، ويُوسَّع بنماذج جديدة عبر `FAL_MODELS_JSON`
**بلا نشر كود**:

```
FAL_MODELS_JSON=[{"id":"kling","nameAr":"كلينغ 2","falPath":"fal-ai/kling-video/v2/master","costCredits":7,"aspectRatios":["16:9","1:1"]}]
```

كل مهمة تحمل مسار نموذجها داخل معرّف المزوّد نفسه، فتتابع نموذجها
الصحيح حتى لو تغيّر الافتراضي بعد إرسالها.

### ⚙️ إعدادات موروثة لكل مشروع

مشروع يحمل نسبة أبعاد وأسلوباً بصرياً افتراضيين اختياريين (`PATCH
/projects/:id` بـ`defaultAspectRatio`/`defaultStyle`، أو عند الإنشاء)
— يُطبَّقان تلقائياً على كل لقطة جديدة في المشروع **فقط حين يترك
المستخدم الحقل فارغاً**؛ اختياره الصريح يتفوق دوماً. مفتاح غائب من
طلب `PATCH` لا يمسّ القيمة المحفوظة (تمييز واضح بين "لم يُرسَل" و"امسح
القيمة" عبر `null`/فراغ).

### 🎬 مشاريع الأفلام والستوري بورد

صانع الأفلام ينظّم عمله في **مشاريع**: مشروع = فيلم، ولقطاته مهام مرتبة
(`shotIndex` يسنده الخادم بترتيب الإضافة). في الواجهة: شريط مشاريع أعلى
الاستوديو، وكل لقطة جديدة تنضم للمشروع المفتوح تلقائياً، ومن بطاقة أي
لقطة: **إعادة توليد** (لقطة جديدة بنفس الإعدادات) أو **أساس للقطة
جديدة** (يملأ النموذج بإعداداتها للتعديل).

المسارات: `GET/POST /api/video/projects`، `GET/PATCH/DELETE
/api/video/projects/:id` — كلها بعزل ملكية صارم (مشروع غيرك = 404).
حذف المشروع يزيل **التجميع فقط**: اللقطات أُنفق عليها رصيد وتبقى في
السجل العام.

### 🎭 بنك الشخصيات (تثبيت هوية البطل)

الشخصية = **وصف حرفي ثابت + ثلاث صور مرجعية** (أمامية/جانبية/خلفية)
تُولَّد مرة واحدة بنموذج صور اقتصادي (`FAL_IMAGE_MODEL`، تكلفة رصيد
واحد). عند إدراجها في لقطة:
1. وصفها الحرفي يُحقن في **مقدمة** البرومت كما هو — لا يُعاد صياغته
   أبداً (إعادة الصياغة أول أسباب تغيّر الملامح بين اللقطات).
2. في وضع image-to-video تُستخدم صورة الزاوية المختارة إطاراً أول
   (رابط موقّع بساعة إن كانت الصور مملوكة على R2).

المسارات: `GET/POST /api/video/characters` و`DELETE
/api/video/characters/:id` — عزل ملكية صارم، فلترة محتوى على الوصف قبل
الإرسال للمزود، خصم مقدَّم واسترداد كامل بتفاصيل الخطأ عند فشل التوليد،
وعدّاد استخدام لكل شخصية. الصور تُنسخ إلى R2 عند تفعيله (فشل النسخ
احتياط شفاف لا فشل).

### 🖼️ الشخصية الثابتة: صورة مرجعية → فيديو (image-to-video)

مشكلة كل أفلام الذكاء الاصطناعي متعددة اللقطات: النص وحده يجعل النموذج
يخترع بطلاً جديداً كل لقطة. الحل المدمج في قالب **"لقطة من صورة مرجعية"**:
ولّد/ارفع صورة بطلك مرة واحدة، واجعلها الإطار الأول لكل لقطة عبر نماذج
image-to-video (المميزة بـ`input: "image"` في الكتالوج — منها Wan
الاقتصادي وVeo 3 من صورة). الخادم يرفض النموذج غير المطابق للقالب
برسالة واضحة بدل 422 غامض من المزود.

خدع مجانية تعمل مع أي نموذج (وثّقناها لأنها تصنع الفرق فعلاً):
- انسخ وصف الشخصية **حرفياً كلمة بكلمة** في كل اللقطات — لا تُعد صياغته.
- اجعل الشخصية بعيدة أو بظهرها للكاميرا في أكثر اللقطات.
- تجنّب القريبة للوجه في النماذج الاقتصادية — فهي مكان الانكشاف.

> رابط الصورة المرجعية يمر بفحص SSRF نفسه (`inspectImageUrl`) — لا
> عناوين داخلية/خاصة أبداً.

### 🎞️ تجميع الفيلم (لقطات المشروع → فيلم واحد)

من الستوري بورد، زر **"🎬 جمّع الفيلم"** يرسل اللقطات المكتملة (بترتيبها)
إلى محوّل التركيب كمهمة `film_assembly` عبر نفس الطابور والأرصدة
(تكلفة رصيد واحد، ودرع التكلفة يشملها): انتقالات (قطع/تلاشٍ/انزلاق/
تقريب)، موسيقى تصويرية، وعنوان ختامي. اللقطات المملوكة على R2 تُوقَّع
بساعة كاملة لصمود انتظار الطابور.

- مع `VIDEO_PROVIDER=mock` تكتمل المهمة بلا ملف (اختبار التدفق) —
  الفيلم الحقيقي يحتاج `VIDEO_PROVIDER=shotstack` + المفتاح.
- 🎵 `MUSIC_LIBRARY_JSON`: مكتبة موسيقى **يملكها صاحب المنصة حصراً**
  (`[{id, nameAr, url}]` لمقاطع مرخصة يستضيفها بنفسه) — لا مكتبة مدمجة
  لأن ترخيص الموسيقى مسؤولية قانونية لا تُفترض افتراضاً.
- 🖼️ **شعار المستخدم**: رابط صورة اختياري في لوحة التجميع (بفحص SSRF
  نفسه) يظهر ثابتاً في الزاوية العلوية اليمنى طوال مدة الفيلم — مسار
  مركّب منفصل أعلى بقية اللقطات. ⚠️ غير مؤكَّد عملياً بعد (بخلاف بقية
  التجميع المؤكَّد على stage) — تحقّق من ظهوره فوق الفيديو لا خلفه في
  أول استخدام حقيقي.
- **إعادة ترتيب اللقطات**: اسحب أي بطاقة في الستوري بورد (سطح المكتب)
  لإعادة ترتيبها — `PATCH /projects/:id/reorder` يرفض أي ترتيب لا
  يطابق لقطات المشروع تماماً (لا فقدان لقطة بصمت).
- 🔊 **مؤثرات الانتقال الصوتية**: `SFX_LIBRARY_JSON` — نفس صيغة مكتبة
  الموسيقى (`[{id, nameAr, url}]`، ترخيص يملكه صاحب المنصة). المؤثر
  المختار يُشغَّل كمقطع قصير عند بداية كل لقطة/ختام (نقاط الانتقال)،
  في مسار صوتي منفصل عن الفيديو والموسيقى التصويرية. ⚠️ غير مؤكَّد
  عملياً بعد (خلافاً لبقية التجميع) — تحقّق من سماعه فعلاً بلا تشوّه
  أو تعارض مع الموسيقى في أول استخدام حقيقي.
- 📝 **كابشن محروق — نمط/موضع/حركة قابلة للاختيار**: كل قالب توليد
  بالذكاء الاصطناعي يحمل حقل `caption` اختيارياً (حتى 80 حرفاً) — لا
  يدخل وصف التوليد إطلاقاً، يُحفظ فقط. عند التجميع، تفعيل خانة "احرق
  الترجمات" يكشف عن:
  - **النمط**: نظيف/عريض جريء/أنيق/ترجمة كلاسيكية/قلم تظليل/مستقبلي —
    قيم `title.style` لدى Shotstack؛ 'نظيف' (minimal) وحدها مؤكَّدة
    عملياً من هذه الخدمة، الباقي من كتالوج Shotstack الموثَّق تاريخياً.
  - **الموضع**: أسفل/منتصف/أعلى الشاشة (نفس آلية موضع الشعار المؤكَّدة).
  - **متحرك (كلمة-كلمة)**: بدل مقطع واحد بالسطر الكامل طوال اللقطة،
    يُقسَّم الكابشن لكلماته وتُوزَّع مدة اللقطة عليها بالتساوي — كلمة
    واحدة كبيرة تظهر في كل لحظة (أسلوب شائع في أدوات صنّاع المحتوى
    القصيرة). مبني بالكامل على مقطع Shotstack المؤكَّد (`title`) — لا
    ميزات كابشن Shotstack الجديدة غير المجرَّبة.
  ⚠️ غير مؤكَّد عملياً بعد — تحقّق من الموضع مع مقاسات 9:16/1:1، ومن
  الأنماط غير 'نظيف'، في أول استخدام حقيقي.

### 🪄 تخطيط سيناريو من فكرة واحدة ("خطّط لي فيلماً")

من الستوري بورد (بعد اختيار مشروع)، زر **"🪄 خطّط لي فيلماً"** يفتح
لوحة تكتب فيها فكرة الفيلم بجملة أو جملتين، ويقترح مزوّد التخطيط
(`VIDEO_SCRIPT_API_KEY`) مسودة N مشهد (2–8، افتراضي 4) — كل مشهد ببرومت
+ كابشن + معايير إخراج (حجم اللقطة/حركة الكاميرا/الإضاءة/المزاج/
الأسلوب) من نفس مفردات `cinema.js` بالضبط. **هذه خطوة تخطيط بحتة — لا
خصم رصيد ولا إنشاء مهمة أياً كانت.** المستخدم يراجع كل مشهد ويعدّله أو
يحذفه، ثم زر "ولّد كل المشاهد" يرسل كل مشهد مقبول عبر
`POST /api/video/renders` العادي تباعاً — بكل حراساته القائمة (فلترة
المحتوى، درع التكلفة، الطابور) بلا أي التفاف عليها.

مخرجات مزوّد التخطيط **لا تُصدَّق حرفياً أبداً**: كل قيمة معيار إخراج
تُقيَّد ضمن خيارات `cinema.js` المسموحة فقط (قيمة خارجها تُسقَط بصمت)،
والنصوص (البرومت والكابشن) تمر بنفس فلترة المحتوى — مشهد يفشل الفلترة
يُسقَط كاملاً بصمت، لا يُفشل الطلب كله لمشهد واحد سيّئ.

بدون `VIDEO_SCRIPT_API_KEY` الميزة مخفية بالكامل (لا زر، لا رابط
مكسور) — نفس فلسفة بقية المزوّدين الاختياريين في هذه الخدمة.

### 🎯 إعدادات منصة بنقرة واحدة

لوحة التجميع تعرض شرائح إعداد سريع (تيك توك/ريلز/شورتس، يوتيوب، منشور
مربع) — نقرة واحدة تملأ نسبة الأبعاد + تفعيل حرق الكابشن + نمطه/موضعه/
حركته دفعة واحدة، بدل ضبط 4-5 حقول يدوياً كل مرة. لا حقل جديد في
الخادم — الشرائح تعبئ نفس حقول `/assemble` الموجودة أصلاً في الواجهة
فقط، فتبقى منطقاً واجهةً محضاً بلا أي مخاطرة خادمية.

### 🎥 قوالب صنّاع الفيديو

ثلاثة قوالب توليد جديدة موجَّهة لصيغ صنّاع المحتوى تحديداً (لا الإعلانات
التسويقية فقط): **قناة يوتيوب بلا وجه**، **ملخص بودكاست مرئي**،
**مراجعة منتج سريعة** — بنفس حقول `ai_clip` بالضبط (وصف + معايير إخراج
+ كابشن)، بلا أي منطق تجميع جديد؛ الفرق كله في التوجيه العربي المخصَّص
لكل صيغة ونسبة الأبعاد الافتراضية المناسبة لها (عمودي 9:16 للقناة/
المراجعة، مربع 1:1 لملخص البودكاست).

- 🗣️ **تعليق صوتي (Voiceover) بالذكاء الاصطناعي**: `FAL_TTS_MODEL` —
  يظهر حقل نص اختياري في لوحة التجميع (٥٠٠ حرف)، يُحوَّل صوتاً عبر
  fal.ai (تكلفة منفصلة عن التجميع، خصم فوري يُسترد كاملاً عند فشل
  التوليد) ويمتد كمسار صوتي طوال الفيلم. **بلا نموذج افتراضي عمداً**
  — نقل طابور fal (إرسال/استطلاع/نتيجة) مُثبَت فعلياً مع الفيديو
  والصور، لكن اختيار نموذج TTS تحديداً ودعمه للعربية مسؤولية صاحب
  المنصة (توثيق fal.ai الفعلي وكتالوجه يتغيّران، وغير متاحين من بيئة
  التطوير هنا). ⚠️ أول استخدام حقيقي يحتاج تحققاً من أن الصوت الناتج
  مفهوم وباللهجة العربية الصحيحة فعلاً، ومن توازن مستواه مع الموسيقى.
- 📐 **دقة الإخراج**: منتقٍ في لوحة التجميع — `sd`/`hd`/`1080`/`4k`
  (Shotstack). `hd` هي المؤكَّدة عملياً (أول تجميع حقيقي نجح بها)؛
  الباقي من كتالوج Shotstack الموثَّق تاريخياً لنفس الحقل. ⚠️ `4k`
  تحديداً **غير مجرَّبة** من هذه الخدمة — لكن رفضها الآن (إن حدث)
  يظهر بتفصيل رد Shotstack كاملاً في سجل الخادم بدل فشل صامت، فأي
  خطأ في القيمة يُكتشف فوراً من أول محاولة. ملاحظة: زمن/تكلفة تصدير
  4K أعلى فعلياً لدى Shotstack بغضّ النظر عن قبول القيمة.
- 💧 **علامة مائية للخطة المجانية**: `WATERMARK_ENFORCEMENT=true` يفرض
  نصاً (`WATERMARK_TEXT`) في الزاوية السفلى اليسرى لكل تجميع لمستخدم
  ليست خطته `pro`/`enterprise` — يُقرأ من ادّعاء `plan` في توكن الدخول
  الموحّد (لا حقلاً يرسله العميل، فلا يمكن التحايل عليه من الواجهة).
  ⚠️ **لا تفعّله قبل التأكد** أن المنصة الرئيسية تُصدر توكناتها الآن
  بادّعاء `plan` (أُضيف في نفس التغيير الذي أضاف هذه الميزة) — توكنات
  صادرة قبل ذلك التغيير لا تحمل الادّعاء، فتُعامَل مجانية افتراضياً
  (القاعدة الآمنة تجارياً) حتى يُجدَّد توكن المستخدم بتسجيل دخول جديد؛
  تفعيلها فوراً بعد النشر قد يضع علامة خطأً على مشتركين مدفوعين حتى
  تنتهي فترة التوكن القديم (٧ أيام) أو يُعيدوا تسجيل الدخول.
- 🎙️ **قسم "هندسة الصوت وAI Voice"**: قسم مستقل في الواجهة (لا مرتبط
  بمشروع) يعرض مكتبتي الموسيقى والمؤثرات كاملتين مع مشغّل معاينة
  مباشر لكل مقطع (`<audio>`)، وحالة تفعيل التعليق الصوتي بالذكاء
  الاصطناعي وتكلفته — عبر `GET /api/video/audio-options` (يتطلب
  تسجيل دخول فقط، لا ملكية مشروع؛ روابط المقاطع نفسها علنية أصلاً
  لأنها تُضمَّن حرفياً في الفيلم النهائي المُصدَّر).

### 🎥 معايير الإخراج السينمائي

قالب اللقطة يعرض تحكّمات إخراجية اختيارية بالعربية — حجم اللقطة، حركة
الكاميرا، الإضاءة، الأسلوب البصري، ووصفاً سلبياً — تُركَّب ترجمتها
الاصطلاحية الإنجليزية في الوصف النهائي (`src/cinema.js`). التركيب في
**نص الوصف** لا في حقول API متعمَّد: حقول النماذج تختلف وتتغير (درس
422 أدناه)، أما الوصف فيفهمه كل نموذج.

> 📌 **درسان من الإنتاج مطبَّقان في `falProvider.js`**: (١) مسارات
> المتابعة تستخدم معرّف التطبيق (أول جزأين) لا مسار النموذج الكامل —
> البناء الكامل يعطي 404 دائماً فتتعلق المهمة حتى المهلة. (٢) fal يقبل
> أي حمولة في الطابور ويؤجل التحقق للتنفيذ — حقل بقيمة لا يعرفها النموذج
> (مثل `duration` رقمياً) يظهر 422 على مسار **النتيجة**؛ لذا لا نرسل
> إلا `prompt` و`aspect_ratio`، وتفاصيل أي فشل تُعرض كاملة.

> ⚠️ **تحقق مطلوب عند أول تشغيل حقيقي**: أسماء حقول مخرجات النماذج تختلف
> بينها (`video.url` / `videos[0].url` / `output.video.url`…). المحوّل
> يجرّبها بالترتيب، وإن جاء نموذج بشكل مختلف يُسجَّل الرد كاملاً في
> السجل ليُضاف شكله — لا نجاح صامت ولا تخمين.

### 💰 تحذير تكلفة
توليد الذكاء الاصطناعي **أغلى بكثير** من تركيب القوالب (قالب `ai_clip`
يكلف 5 أرصدة مقابل 1-2 للقوالب). قبل تفعيله بمفتاح مدفوع راجع **درع
التكلفة** أعلاه — خصوصاً `STARTER_CREDITS=0` و`DAILY_RENDER_CAP`.

## 🗃️ ملكية ملفات الفيديو (R2)

**بدون تفعيلها**: الفيديو يبقى على استضافة المزوّد المؤقتة — لا تملك الملف
ولا تتحكم بعمر رابطه. مقبول للتجربة، **غير مقبول لوعد "فيديوهاتك لك"**.

**بتفعيلها**: فور اكتمال التصدير يُنسخ الملف إلى دلوك الخاص، ثم:
- الدلو **خاص دائماً** — لا رابط عام أبداً.
- كل تنزيل يمر بمسار `/api/video/renders/:id/download` الذي **يتحقق من
  ملكية المهمة** ثم يوقّع رابطاً صالحاً دقائق معدودة (10 افتراضياً).
- حذف تلقائي بعد `VIDEO_RETENTION_DAYS`، ويُمسح الرابط معه فلا يبقى
  وعد بملف غير موجود.

### التفعيل
1. Cloudflare → R2 → أنشئ دلواً (اتركه **خاصاً**).
2. R2 → Manage API Tokens → أنشئ مفتاحاً بصلاحية القراءة والكتابة عليه.
3. في Render أضف: `VIDEO_STORAGE=r2` و`R2_ACCOUNT_ID` و`R2_ACCESS_KEY_ID`
   و`R2_SECRET_ACCESS_KEY` و`R2_BUCKET` → أعد التشغيل.
4. تأكد من `/api/health` أنه يعرض `"fileStorage":"r2"`.

**لماذا R2 تحديداً**: بلا رسوم نقل بيانات صادر — والفيديو ملف كبير
يُنزَّل مراراً، وهذا البند هو ما يفاجئ الفاتورة لدى مزودي التخزين
التقليديين.

> فشل النسخ **لا يُفشل المهمة ولا يهدر رصيد المستخدم**: يبقى رابط
> المزوّد كاحتياط شفاف (تعرضه الواجهة بوسم "مستضاف لدى المزوّد")
> ويُسجَّل الفشل.

## 🚫 فلترة المحتوى — ما تفعله وما لا تفعله

**تفعل**: منع الروابط داخل نصوص الفيديو (قناة سبام)، والمحارف المخفية/
قالبة الاتجاه، والتكرار المفتعل، وروابط الصور التي تشير لعناوين داخلية،
وأي مصطلح في `CONTENT_BLOCKLIST`.

**لا تفعل**: إشرافاً دلالياً على المعنى. لا قائمة كلمات تكفي لذلك.
للإطلاق التجاري الواسع أضف واجهة moderation مخصصة كطبقة إضافية —
البنية تستوعبها بلا تغيير العقد.

## 🔑 تدوير مفتاح JWT (بلا إخراج المستخدمين)

السر الواحد يربط النظامين، فتدويره يحتاج ترتيباً:

1. **خدمة الفيديو**: `JWT_SECRET_PREVIOUS=<السر القديم>` و
   `JWT_SECRET=<الجديد>` → أعد التشغيل.
2. **المنصة**: نفس الخطوة (`backend` يقبل السرّين أيضاً) → أعد النشر.
   التوكنات القديمة تبقى صالحة، والجديدة تُوقَّع بالسر الجديد.
3. **بعد ٧ أيام** (أطول صلاحية توكن حالياً): احذف `JWT_SECRET_PREVIOUS`
   من الخدمتين — تنتهي فترة التدوير.

> ملاحظة صريحة: صلاحية التوكن ٧ أيام. تقصيرها يتطلب آلية refresh token
> في المنصة (خارج نطاق هذه الخدمة) وإلا خرج المستخدمون باستمرار.

## تسليم التوكن من المنصة (SSO)

من أي صفحة في المنصة الرئيسية بعد تسجيل الدخول:

```js
window.open(`https://<نطاق-خدمة-الفيديو>/?token=${localStorage.getItem('token')}`);
```

الواجهة تلتقط `?token=`، تخزنه محلياً، وتحذفه فوراً من شريط العنوان.

## النشر على Render (بنقرات معدودة)

بجذر المستودع ملف `render.yaml` جاهز:

1. لوحة Render → **New → Blueprint** → اختر مستودع `jaola-os`.
2. أدخل عند الطلب: `JWT_SECRET` (**نفس** سر المنصة حرفياً — هذا هو الدخول
   الموحّد) و`ADMIN_USERS` (نفس قائمة المشرفين).
3. **Apply** — يظهر رابط الخدمة خلال دقائق، وجرّبه: `/api/health`.

### 🔴 مهم: الدوام (وإلا ضاعت أرصدة المستخدمين)

بلا `DATABASE_URL` تُخزَّن الأرصدة والمهام في ملفات على قرص Render
المجاني وهو **مؤقت** — تُمسح مع كل إعادة نشر. الحل مجاني:

1. أنشئ قاعدة PostgreSQL على [Neon](https://neon.tech) أو
   [Supabase](https://supabase.com) (باقة مجانية تكفي البداية).
2. انسخ رابط الاتصال (`postgresql://…`) وأضفه في Render كمتغير
   `DATABASE_URL`.
3. أعد التشغيل — **تُنشأ الجداول تلقائياً** عند أول إقلاع، ويعرض
   `/api/health` الحقل `"store":"postgres"` تأكيداً.

مكسب إضافي: العمليات تصبح **ذرّية على مستوى قاعدة البيانات** (لا خصم
مزدوج ولا استرداد مكرر حتى مع طلبات متزامنة أو نسخ خدمة متعددة).

### ربط زر الاستوديو في المنصة (بعد النشر)

بعد أن يصبح لديك رابط الخدمة، أضفه كمتغير بناء في مشروع **الواجهة**
(Vercel → مشروع jaola-os → Settings → Environment Variables):

```
VITE_VIDEO_STUDIO_URL = https://jaola-video.onrender.com
```

ثم أعد النشر — يظهر زر 🎬 في شريط لوحة التحكم يفتح الاستوديو بتوكن
المستخدم الحالي تلقائياً. **قبل ضبط المتغير لا يظهر الزر إطلاقاً** (لا
رابط مكسور ولا عنوان مخمَّن).

للفتح اليدوي في أي وقت:
`https://<رابط-الخدمة>/?token=<توكن المستخدم>`

## الربط بمزود حقيقي (Shotstack)

1. أنشئ حساباً مجانياً في Shotstack وخذ مفتاح **stage**.
2. `VIDEO_PROVIDER=shotstack SHOTSTACK_API_KEY=... npm start`
3. نفّذ أول تصدير تجريبي وتحقق من وصول الفيديو فعلاً — صيغة الطلب/الرد
   مكتوبة وفق التوثيق العام ويجب تأكيدها عملياً في أول تشغيل قبل أي
   اعتماد إنتاجي (انظر التحذير داخل `src/providers/shotstackProvider.js`).
4. الانتقال للإنتاج: `SHOTSTACK_ENV=v1` بمفتاح الإنتاج — قرار صريح منفصل.

## الضمانات المالية (القاعدة الذهبية)

- **لا تنفيذ بلا خصم مسبق** — مهمة بلا خصم مثبت لا تدخل الطابور.
- **فشل المزود لا يكلف المستخدم** — استرداد تلقائي معصوم من الازدواج
  (idempotent لكل مهمة، حتى عبر انهيار العملية في منتصف الحسم).
- **كل حركة رصيد مسجلة** في سجل تدقيق append-only (منح/خصم/استرداد/ترحيبي).
- **مهلة قصوى 15 دقيقة** — لا مهمة معلقة تحتجز خصماً للأبد.
